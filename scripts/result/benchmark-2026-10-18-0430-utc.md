# Benchmark Indexing SrcInsight — Zod, 2026-10-18 (Linux)

Date: 2026-10-18 04:30 +07:00 local (2026-10-17 21:30 UTC) · Corpus:
`ProjectTest/zod-main` in place (`--no-copy`, original fixture untouched —
`.srcinsight` removed afterwards, sync touch reverted by the script).

This run measures the current HEAD, which adds 1-indexed identifier columns to
call-site locations: `model.Range.StartCol/EndCol`,
`links.site_start_col/site_end_col`, `loose_ends.site_start_col/site_end_col`,
and widens `idx_links_identity` to include the column pair (schema v19–v23).
This is the cross-check that the extra columns do not distort indexing wall
time on the standard corpus. Three fresh runs were done
(`scripts/benchmark.sh --no-copy --runs 3`).

**Comparability caveat:** this is Linux on the same physical box as the Windows
docs, but the corpus snapshot and schema differ from `benchmark-2026-10-13-1221-utc.md`
(fewer entries and loose ends, more links — see Comparison). Cross-doc timing
deltas are therefore **not** apples-to-apples and no regression/improvement claim
follows from them.

## Per-identifier column feature

Schema v19–v23 adds a 1-indexed identifier column pair to each resolved link and
loose end (`StartCol` inclusive, `EndCol` exclusive, tree-sitter style). On this
corpus:

- 100% of `links` (87,417) and `loose_ends` (46,309) carry `site_start_col > 0`.
- **637** `(origin, target, kind, site_start)` groups hold more than one row,
  i.e. multiple references on the same line that the old line-only identity
  index collapsed into a single row. These now persist as distinct rows, which
  is the intended effect of widening `idx_links_identity`.

The fresh-index numbers show no visible distortion from the extra columns; the
dominant phases remain parse and resolve, and search/stat paths stay flat.

## How to reproduce

```bash
# Requires: Go 1.26+, CGO toolchain, sqlite3
go build -o ./srcinsight ./cmd/srcinsight
bash scripts/benchmark.sh --root ./ProjectTest/zod-main --runs 3 --no-copy
```

Verify DB contents:

```bash
DB=./ProjectTest/zod-main/.srcinsight/srcinsight.db
sqlite3 "$DB" "SELECT COUNT(*) AS entries FROM entries; SELECT COUNT(*) AS links FROM links;"
sqlite3 "$DB" "SELECT kind, COUNT(*) FROM links GROUP BY kind ORDER BY COUNT(*) DESC;"
sqlite3 "$DB" "SELECT COUNT(*) FROM links WHERE site_start_col > 0;"
sqlite3 "$DB" "SELECT MAX(version) FROM ledger_versions;"
```

(Remove `ProjectTest/zod-main/.srcinsight` afterwards to leave the fixture
pristine.)

## Notes

- The fresh-run spread (10.92–11.35s, 0.43s) is quiet compared with the 3.84s
  spread on 2026-10-13, so the isolated effect of the extra columns is well
  below this box's run-to-run noise.
- Fresh peak RSS (~350 MB) is higher than 2026-10-13 (~266 MB), but RAM
  measurement differs (`/usr/bin/time %MKB` here vs `WorkingSet64` sampling on
  Windows) and the fixtures differ; this is not a like-for-like memory delta.
- The 86 MB database (vs 81.3 MB) reflects both the different corpus and the
  extra integer columns plus the widened unique index on `links`.
